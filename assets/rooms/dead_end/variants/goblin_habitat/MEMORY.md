# 项目美术记忆

## 山洞常用材质配色（2026-09-08）
用户要求：地下阴暗潮湿环境中的骨头应是偏棕黄的浅黄色；木头需要明显区分，采用深棕色。后续房间优先复用，不恢复纯白骨头或金黄色木材。

| 用途 | sRGB HEX | sRGB RGB (0–255) | 应用方式 |
| --- | --- | --- | --- |
| 旧骨：羊头骨、地面残骨 | #8A6D43 | 138, 109, 67 | 基准色，保留扫描明暗、近地泥渍与斑驳 |
| 深棕木材：棚架、木板、头骨木桩 | #AB8662 | 171, 134, 98 | 材质乘色，与原树皮纹理及顶点明暗相乘 |

机器可读的唯一色值来源为 model/palette.json，room.mjs 直接读取。上述不是截图取色；最终亮度受贴图、补光和色调映射影响。复用时保留对应材质应用方式；不要将其直接视作最终像素值。
木棚形状与配色已获用户认可，后续未经新要求不要改动。

用户连续复核木色仍偏深，最新材质乘色为 #AB8662（171, 134, 98），用于让树皮纹理更清楚；替代此前 #6B4830 和 #896447。


## 26 个版本复盘：以后开始美术工作前必须阅读

### 当前验收结论与复盘边界
用户在 V0.26 表示“终于满足我的最低要求”。这是当前房间的最低美术验收线，不等于精品最终资产、团结引擎集成完成或手机性能验收通过。不能把“用户愿意继续”解释成无需再改进。
以下依据本任务的用户反馈、模型 README 的版本规范与实际检查记录整理；不把用户后续新增的数量、配色或布局偏好倒推成最初已明确的要求。真正反复出现的问题是：没有把已知信息转成整体设计，没有及时自查明显的视觉错误，把发现问题的工作交给了用户。

### 核心失误
我过早编写几何生成代码，缺少对参考图结构、尺度、材质和形成原因的拆解。之后主要靠局部参数修补，甚至用更多几何、随机扰动和遮挡掩盖基础结构错误。自动检查只能说明部分技术约束成立，不能证明模型自然；我却多次在仍有明显视觉问题时结束交付。

### 具体错误、成因与防止复发的规则

| 方面 | 已出现的问题 | 下次必须执行的规则 |
| --- | --- | --- |
| 参考图阅读 | 漏看棚屋开口朝右、屋面坡度、三角木架、柱头露出、柱旁木板等显著结构，等用户逐项指出。 | 建模前用文字列出朝向、轮廓、承托点、遮挡关系、主要材质和比例；正面、侧面、俯视都要核对。不能只记“一个茅草棚”。 |
| 美术前提 | 早期给盲眼哥布林的栖居处安排火把，没有把设定落实到环境。 | 先阅读世界观与房间用途，解释每个道具为什么存在；预览补光与游戏内光源必须分开。 |
| 门位表达 | 概念图和示例位置容易被理解为门固定在正中。 | 明确区分房间门位候选、单次实例和最终随机布局；预览标注示例，不暗示永久固定。 |
| 初版精度 | 用粗糙基本体就进入用户审阅，头骨、木材和兽皮尤其明显。 | 基本体只能用于内部尺度验证。提交美术预览前，至少主轮廓、关键孔洞、材质和接触关系应成立。 |
| 制作方法 | 对头骨等识别度高、形态复杂的物体坚持简单程序化拼接，投入多轮仍不像。 | 先判断手工建模、扫描资产或程序化哪种更适合；已知简单拼接不足时尽早换方法。用户允许的范围内寻找许可清楚的资产，不让用户反复推动。 |
| 棚屋朝向 | 模型开口朝前，和参考图朝右不符。 | 在配置和模型元数据中明确方向，使用坐标轴核对，不凭相机视角猜测。 |
| 哥布林尺度 | 棚子先过高，缩小一次仍过高，缺少与居住者和参考物的对比。 | 用固定人物尺度或比例标尺核对入口、承托高度、占地；“哥布林的棚”不沿用人类棚屋默认尺寸。 |
| 屋顶结构 | 坡度过平，同侧柱等高，屋面弧度机械规整。 | 先确定四个独立承托点，再生成梁和屋面；本项目四角高度见下方当前基准。 |
| 柱子姿态 | 支柱过于垂直，右侧柱没有参考图的外撇角度。 | 检查柱脚、柱顶和承托关系；歪斜要有明确方向和程度，不能只加不可见的小扰动。 |
| 柱头与木架 | 左侧柱头没有越过茅草，三角撑架、破木板没有及时复现。 | 木架应独立成立，柱头、节点、撑杆要先做，再覆盖草层，不能靠草掩盖木架缺陷。 |
| 草层颜色 | 用干燥金黄表现潮湿洞穴中的茅草，缺少厚重深黄深棕和腐朽感。 | 材质颜色由环境、含水状态和使用历史决定；不能直接沿用户外干草默认色。 |
| 草层厚度 | 草铺得稀、薄、规整，露出不合理结构。 | 从短密底草、重叠草束和散乱草端形成厚度，检查屋面遮蔽和边沿体积。 |
| 草束方向 | 先全部朝右，后又全部瞄准最短柱，形成明显方向规则。 | 以局部坡向和铺设簇为主，允许侧偏、弯折、交叉和错层；随机必须服从屋面结构。 |
| 草檐覆盖 | 只做右侧下垂，前侧没有；补上后又全部平行。 | 同时检查每个可见檐口与转角；根部、弯曲、长短、方向都不能复制粘贴。 |
| 草顶底层 | 用三层不规则多面体充当厚草，露出后像板子。 | 用能解释真实材料组成的结构补厚度；不在可见位置放与材料不符的封底。 |
| 草檐衔接 | 顶面草和垂草像两部分，出现一圈接缝。 | 草束根部应深入屋面，连续跨过边沿弯下，不能在檐口齐刷刷起止。 |
| 过度遮掩 | 为遮住木架不断加密前檐，后来又发现概念图需要露出结构。 | 先确认哪些结构该露、哪些该遮。修结构错误，不用更多草、碎石或装饰遮丑。 |
| 绳结 | 缠绕等距整齐，像精工制作。 | 围绕承力节点做错向缠绕、结扣和散尾；保留绑扎逻辑，不能只做均匀螺旋。 |
| 木材 | 早期木纹假，后续整体压色过深，连续几轮才调到合适亮度。 | 在真实纹理、顶点色、材质乘色和当前灯光共同作用下调色；一次给出可辨认但不过量的变化，并检查木纹可读性。 |
| 兽皮 | 像平面剪影，轮廓、毛感、厚度、翻边和褶皱不足，和参考图不符。 | 使用合适的毛皮材质并保留真实体积；褶皱、叠放、卷边和地面接触共同验收。PBR 纹理不等于模型本身真实。 |
| 头骨与残骨 | 头骨解剖结构不可信；长骨像两端圆球的狗零食；肋骨是等距半圆。 | 识别性结构优先使用可靠几何，保留不对称关节、孔洞和残缺；不要用通用符号替代解剖形态。 |
| 骨色统一 | 地面骨改黄后，羊头骨仍白，材质类别没有统一处理。 | 同一材质族共享调色基准并保留原明暗；逐一核对实例，不只改被点名的一个网格。 |
| 材质色值 | 把“深棕”“浅黄”当作单个常量，忽略纹理乘色和曝光，多次过白或过黑。 | 从 palette.json 读取，记录色彩空间和应用方式。材质值不是最终像素值，不改全局光照来掩盖单件材质问题。 |
| 右侧大岩体 | 太小、太长、压迫感不够，上宽下窄仍像规则形体，顶部没有接顶。 | 先做大轮廓、占地和高度关系，多个视角检查体量；本房间保留已认可的短占地、上宽下窄、接顶形体。 |
| 墙地过渡 | 泥土和岩壁分界像裁切；后来只在墙脚变脏，上部岩面仍过干净。 | 墙脚、缝隙、上向岩面、渗水区分别处理泥土积存，不把污渍限制在固定高度带。 |
| 岩壁基本形 | 随机摆放大量圆石像鹅卵石墙；改尖角后变成随意堆叠的多面体。 | 先确定连续母岩、尺度和断裂关系，再加局部破碎；“乱”和“尖”都不能代替自然成因。 |
| 岩壁修补 | 积土出现独立三角形边界，明显像贴片；岩面贴图在上向断面拉伸。 | 泥色渐变融入实际岩面，检查边界；按面朝向和几何用途检查 UV，不能只验证存在 UV 属性。 |
| 岩壁裂隙 | 改为大岩面后裂纹太粗、太黑、像规则分区线。 | 裂隙应有连续、渐隐、宽窄和方向变化，不让全墙都呈现完整闭合边框；结合参考区分断裂面与溶蚀面。 |
| 岩壁倾斜与细节 | 墙体过于竖直；轻微改动视觉上仍不足；纹理单一、长条过齐。 | 用实际顶部/底部位移核对倾角，并看远景轮廓；结构要包含大面、中层岩脊、小沟槽和材质差异，不能用同一频率噪声覆盖。 |
| 钟乳石穿插 | 靠墙放置但忽略墙面凸起，多根穿入墙体。 | 用修改后的实际几何范围重新验算，再看渲染。移动或放大岩壁后，重新检查柱体；不是只检查中心点。 |
| 钟乳石规律性 | 大柱过多、等粗、平行、排列整齐；单个形体像光滑旋转圆锥/细腰管。 | 当前只保留三组，独立粗细和轻微错向；加入沉积起伏、底部簇生石笋和顶部附属钟乳石，附属体不能全部埋在主干内。 |
| 石柱与通路 | 加粗和扩展附属体后，后柱包络侵入通路；到测试阶段才发现。 | 造型方案先考虑可用空间；变形后更新包络，修复位置，不放宽通路规则来使测试通过。 |
| 落石布局 | 新增大落石占在房间中部，后续用户要求移至墙边。 | 记住当前墙边偏好；落石应围绕崩落来源、主要动线与视觉重点布置，新增数量并非越多越好。 |
| 滴水 | 最初节奏整齐，部分点缺少可信的钟乳石来源；视角切换可能看不到效果。 | 来源绑定真实尖端，稳定选择并记录周期/相位；在实际审阅视角检查运动。保留棚顶截断与檐口二次滴落逻辑。 |
| 水与环境关系 | 滴水下方缺少积水，补水坑后偏绿、像实色贴片。 | 以首个实体落点定位，地面水坑贴合地形、带不规则边界与泥地透色；棚顶/凸起岩石落点不能直接生成悬空地面池。 |
| 整体自查 | 用户承担了大量明显问题的发现：方向、数量、对齐、假材质、穿插、单侧缺失。 | 交付前把自己当审阅者，按参考图逐项列差异并修正，不满足于“比上一版好一点”。 |
| 技术与美术验收 | 多次用测试通过、增加三角形数或构建成功结束回复，但这些不能证明视觉正确。 | 技术检查与视觉检查分别报告。测试确认尺寸、确定性、来源、碰撞包络等；美术必须看完整材质、灯光和实际 WebGL。 |
| 视角对照 | 多轮视角、缩放或补光不一致，容易把构图差异误当模型改进。 | 尽量固定一个全景和一个近景做前后对照，再补侧面/俯视；用户正在操作时不覆盖其偏好，必要时说明对照视角。 |
| 交付措辞 | 说“已检查实际渲染”容易被理解为所有可见问题都已解决，但检查深度不够。 | 报告看了哪些部位、解决了哪些问题；不说“完美复刻”“已达到正式上线品质”，不把最低验收说成最终完成。 |
| 改动组织 | 在长函数内反复加条件和参数，局部修补增加耦合，部分旧规范留在文档中。 | 新资产应明确配置、生成、材质、放置和动画责任；先读当前基准，再看历史规范。不要在美术改动途中擅自大重构。 |
| 随机序列 | 共享随机流会使修改墙面影响已认可的草屋、装饰；需要保存流或消费旧次数才能保形。 | 新模块使用独立命名种子/随机流。对已认可对象做几何回归；当前兼容代码不可轻率删除。 |
| 构建流程 | prebuild 从压缩分片还原 GLB，若分片没更新，会覆盖刚导出的模型。 | 顺序必须是生成模型、验证、更新 packed 分片、构建；最后核对网页与下载 GLB 是同一版。 |
| 测试效率 | 反复 buildRoom 和大量落点射线让全套测试耗时明显增长，之后又多次重复检查。 | 初次跑必要全套，后续只对新改动和风险做有意义的检查；几何不变的调色不反复跑全部昂贵几何测试。失败必须修复，不藏在构建成功后面。 |

### 当前已认可基准，不能在下一轮退回旧方案

- 房间：8×8×4m，洞穴哥布林栖居处，无固定火把。south door 是示例门位，不是固定开门规则。
- 棚屋：低矮、开口向右（东），四角不等高；湿草深黄深棕，厚而凌乱、草檐连续，三角木架可见，柱边破木板、乱绳结、褶皱兽皮。
- 四角承托高度：左后 1.55m，左前 1.395m，右后 1.3175m，右前 0.6975m。承托点不等于伸出的柱头；左柱头露出草顶，右柱外撇约与地面 70°。
- 骨：使用目前已认可的扫描几何；地面残骨来源为人体骨骼，不能称为动物骨扫描。羊头骨与残骨共享棕黄旧骨色。
- 木材：保留上文最新 #AB8662 乘色，旧骨 #8A6D43；不得退回此前被否定的过黑木材或亮白骨色。
- 右侧大岩体：保持原样。墙面采用连续母岩；左墙强化内倾及多尺度不规则层理，不恢复随机附着圆石或规则多面体堆。
- 大石柱：三组，粗细不同、细腰主干带沉积起伏，底部与顶端有附属簇生结构；不能把小附属体计为新增大柱。
- 两块大落石：位于墙边，中央主要通路保持畅通。
- 顶部滴水：当前登记 50 个原有小钟乳石尖端，选 10 个，含原棚上两点与另选八点，周期/相位不同。V0.26 新增的是大柱附属结构，没有自动计入此基数；若后续用户要求所有尖端参与，必须显式更新统计，不能仍宣称全场全部尖端都按 20% 计算。
- 水坑：实际地面落点下生成、贴地、暗色半透明。水滴遇到首个实体表面停止。
- V0.26 是最低美术基准。仍未完成正式引擎碰撞、LOD、移动端性能、联机或随机地图运行验收；不能由当前单房间约 23.4 万三角形推断整张地图手机表现。

### 下一次交付前的固定流程

1. 先读本文件、palette.json 和适用模块 README。把用户最新要求与已认可部分分清；历史条款冲突以最新明确要求为准。
2. 拆参考图：大轮廓、尺度/方向、受力或地质结构、材料状态、接触/遮挡关系。不能从一张概念图推出它未给出的精确隐藏结构。
3. 选择制作方式和复用资产，确认来源许可及修改说明。程序化材质、扫描几何、亮度推导法线分别准确标注。
4. 先写规范与能约束真实行为的测试，再实现；先修结构再补材质和装饰。分模块使用独立随机种子。
5. 在真实网页全景、近景和需要的侧面检查：是否像参考、是否机械重复、纹理拉伸、过亮/过暗、穿模、悬空、通路受阻。水与动态效果至少观察不同时间点。
6. 自查发现明显问题先自行改进，不能把每次尚有明显缺陷的中间状态作为完成品交给用户；也不擅自修改已认可部分。
7. 更新导出、分片与必要的配色记忆，核对版本，完成相关测试与构建。清楚报告仍需用户审阅的美术部分，不把技术通过当成视觉验收。

记忆维护：本文件是项目内持久记忆，可随仓库复用，不等同于已写入账户级长期记忆。入口见本目录 AGENTS.md。用户后续改变偏好时，更新“当前基准”和配置；历史错误记录保留并注明替代关系。
