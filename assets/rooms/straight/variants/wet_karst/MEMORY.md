### 我犯的错误、原因和防止重犯的办法

根本问题是：没有先准确拆解参考图中的实体比例、负空间与自然结构，就开始堆几何和材质；随后又把局部修复、随机变化、测试通过误当成整体可信。用户因此承担了本应由我完成的基础审查。

| 错误 | 后续必须执行的规则 |
|---|---|
| 首版岩壁只有约2.7m，参考要求约5–6m；宽度相似就误判结构合格，丢失侧边洞穴感。 | 先比长宽高、占地、实体厚度与内部净空的比例，再比细节；用俯视标出相邻地标。最新的相对布局反馈优先于早期固定长度。 |
| 前后、左右和收束方向理解反了，做成后方变宽、两头贯通。 | 写清入口-Z、后方+Z、左墙-X；用俯视草图确认前侧开口、后端向母岩收束封死，不靠口头推断。 |
| 把单层扫描岩面当完整岩体，主岩壁和内侧墙分别暴露过纸片边。 | 使用扫描素材前检查表皮/实体；检查侧面、背面、端部与多截面厚度，双面材质不能代替体积。 |
| 补厚后变成等厚大石板；后来有厚度变化仍与凹穴净宽比例不符。 | 检查纵深和高度上的厚薄变化、自然曲率及厚度/净空比例，不能只测“厚度大于某值”。 |
| 为留洞穴把整段底部抬空；前端过早顶到屋顶。 | 岩体连续接地，空隙在其侧后方；岩冠前低后高逐渐接顶，检查母岩连接与真实承托。 |
| 延长或弯曲岩壁后挡住洞口、骸骨；只从洞内看得到就当入口可见。 | 用玩家入场眼高验证遮挡和发现性；移动主物体联查骨堆、石笋、碎石、滴水，不只改坐标。 |
| 声称五面完成，但过渡带太窄，用户侧视仍只有两面。 | 数学上的中间法线不等于可读的过渡面；必须从用户相同角度看见有实际宽度的正外/正内肩部及连续弧度。 |
| 碎石随机摆放却像复制品、围成项链；后来的堆石又像人工叠放。 | 同时变化断裂轮廓、长宽厚、姿态、入土程度、簇密度与留白；分布遵守崩落和重力逻辑，不能只随机坐标。 |
| 石笋过多、摆在内侧、成队列，并与岩壁穿模。 | 按参考区分短石笋和贯穿柱；检查整个高度、半径及倾斜包络和彼此间距，中心点在岩壁外不代表无穿模。 |
| 扫描图集被错误拉伸到新增断面；消除拉丝后又留下胶带状接缝、拼块与色差。 | 区分扫描UV图集和可平铺PBR；统一米制尺度、法线和材质过渡，烘焙后检查实际GLB的UV方向与切线空间。 |
| 明知前断面严重拉伸，仍以“扣分项”交付；漏掉明显穿模。 | 已知明显拉伸、破面、穿模是交付阻断项，必须修复；不能靠结构评分80或测试全绿抵消。 |
| 岩脚黑边和悬空感、矿物平切根部、水面实色或规则亮条纹，暴露程序化拼装。 | 先检查真实接触和几何，再检查AO与反射；水面需多尺度、不规则变化，不能用调灯掩盖结构缺陷。 |
| 过度关注左岩壁和剖顶全景，忽略室内天花板像多层板拼接。 | 每轮保留完整洞顶的室内眼高检查；顶墙需连续轮廓、法线和纹理，洞顶修改后联查钟乳石根部与滴水路径。 |
| 蛛网嵌墙却只换材质或向外平移，仍挂在不合理的墙中央。 | 先确定角落、跨面锚点与悬空空间，再做网丝；按实际岩面检查净距和锚点，不能用长牵引线补救错误位置。 |
| 角落网呈三角渔网/吊兜；圆网外延与内部放射丝不对齐。 | 以自然参考确定网型；当前复用平面圆网，外延必须沿现有放射丝连续共线连接，不凭印象拼线。 |
| 支撑数量够了但全靠上方，遗漏左右下方；缺少网外横向加固。 | 分别验证左上、左下、右上、右下覆盖；主体高度限制不能错误限制延长丝。横向加固端点必须真正落在支撑丝上。 |
| 细丝像素断续、过亮，素材搜索结果也不等于适用资产。 | 在实际观看距离检查透明度、粗细与抗锯齿；下载后看外观与源站许可，不把自建几何说成下载模型。 |
| 大纹理导出引起加载失败、白墙或崩溃风险；只看文件大小或几何字节不足以判断内存。 | 检查最终GLB及纹理解码、控制审阅贴图分辨率；区分文件、CPU/GPU几何、纹理与整页内存，性能结论必须说明测量范围。 |
| 旧服务/缓存或错误资源响应可能让看到的并非最新导出；“构建通过”不保证浏览器正确显示。 | 核对资产版本、资源类型与加载错误，实际打开导出物；页面ready不能掩盖贴图加载失败。 |
| 自评81与用户40差距巨大；只针对最新投诉修补，没有重审整个对象。 | 每次先列可见差距，再评分；主体比例或空间关系错误不得达到80。修复后检查全部结构和关联对象，用户评价优先。 |

### 下一个房间必须执行的顺序

1. 拆分主要物体，逐项列概念图中的方向、比例、轮廓、负空间、接触、材质和依附关系；标出要保护的已认可资产。
2. 在模块README写规范，先写能暴露旧缺陷的测试，再实现。测试验证真实几何关系和导出行为，不能仅验证参数存在；视觉质量由实际渲染单独审查。
3. 先完成一个物体的整体体积与空间关系，再细化材质、碎石等细节。每个单体达到有证据的80分后才进入下一个，不能靠整房平均分过关。
4. 每轮从同参考视角、俯视、入口眼高、侧后方和接触近景比较；检查完整洞顶。修复一点后必须联查邻近对象，保护既有认可成果。
5. 明显缺陷先修好，不把用户当质量检查员。记录分项扣分、截图、版本和测试结果；自评、用户单体认可、整房可用、引擎可用分别记录。
6. 整房最后统一检查视觉、路线、封墙状态、滴水、导出加载与资源预算，再提交。发现错误后继续执行修复，不停在重复解释。

归因边界：用户后来提出“骸骨再藏深一点”、明确指定平面圆网和支撑细节，是设计逐步细化，不应倒写为最初漏做的需求；但不合理的实体、穿模、缺少可信支撑以及收到反馈后仍未落实，是我的责任。
