# 直通房建模规范

ST001：采用米制，Y 向上，北 +Z（与配置方向一致）；占用 X/Z±4，Y0–4。南北必接门的底边中心为 (0,0,±4)，净宽2m净高3m；实际射线检查门洞及穿行路线。
ST002：主通路 |X|<1 从南贯通至北，人物高度1.8m范围内不得被岩壁、矿物、落石挡住。左倾岩体从西侧斜向内下方伸出，地质细节依附连续母岩，不使用随机圆石拼墙。
ST003：东南水潭位于 (+2.6,-2.5)，半径约0.85×0.72m，不占门净空。地面真实凹陷形成盆底，水平水面低于岸边；滴水起点必须在真实钟乳石尖端，下落到水面后产生涟漪；节奏独立可复现。
ST004：大柱两组，边缘放置，细腰、粗根冠、不同高度卫星石笋；50个小钟乳石中10个滴水（包含潭上两处），其余滴水下方浅水坑。材质有多尺度溶蚀和积土，不均匀噪声替代所有结构。
ST005：网上下载岩石与泥土的真实 PBR 材质，来源与许可记入 THIRD_PARTY.md；真实残骨扫描沿用已认可资产及配色。GLB自包含，不导出审阅灯光。单房审阅预算30万三角形，非手机运行保证。
ST006：room-identity.json 的 roomId、roomName、prefabKey、roomRevision 对应正式配置，GLB extras 和 model-info 保留一致关联。输出使用新文件，不改第一房。
ST007：独立 seeds 隔离墙壁/矿物/碎石/滴水；生成前后结果可复现。导出检查有限坐标、材质引用、内嵌图像和统计。

视觉验收：全景30、岩壁与矿物25、水潭滴水20、材质15、细节接触10，总100，实际运行并记录不足后修改至自评≥80再交付。不得以测试通过代替视觉评分。门、导航、LOD和真机仍需团结引擎验收。

ST008：左倾主岩体加入 Poly Haven Rock Face 01 扫描几何，保留UV与真实颜色/法线/ARM，仿射缩放倾斜适配占用；GLB总计9张纹理。

ST009：水面加入数学波纹生成的法线纹理（非扫描），以微波打散平面反光；预览缓慢移动法线，落水圈仍绑定滴水时序。最终纹理总数10。

动画时序唯一实现为 water.mjs，模型测试与网页共同导入，避免同一滴水规则维护两份。相同输入时刻可复现；GLB仅保存参数。

ST010（用户纠正）：左侧主岩壁沿南北方向长5–6米；保持已认可宽度范围，中心下部向墙侧退让形成真实凹穴，不能只拉长一块实心石头。用实际包围盒和凹穴射线验证，俯视及低视角再确认。
ST011（用户纠正）：移除岩脚等距/圆环排布。碎石用不同断裂形状、长宽高比例、翻滚角度，沿少量崩落堆成簇，保留空隙和泥土露出；禁止把同一正多面体只缩放后重复一圈。主要岩脚碎石使用独立种子，不影响水潭一侧既有布局。

ST012（侧面薄片纠正）：左主岩壁不能把扫描的单层表面当实体。保留5.7m长与墙后凹穴，向通道侧补0.55–0.75m厚的岩体，封闭可见边界；不同高度/纵向截面的射线必须穿过两层表面。侧面、端部、凹穴和俯视都需真实渲染检查。为维持30万面预算，平缓地面网格可从140降至120分段，水盆与滴水落点测试不得放宽。

ST013（已纠正方向，当前规则）：以配置坐标为准，南侧-Z是入口/前方，北侧+Z是后方；左侧-X。曲线岩壁在入口侧展开，越向北越向西墙收束，最终与母岩交叠封闭。旧“前端向西收回”解释错误，已废止。保留非线性曲率、5–6m纵深、实体厚度和南侧凹穴口。
ST014：凹穴只能从南侧进入，北端封死。用实际岩体/母岩射线检查前向出口及后向阻挡，不能只检查可见外表。凹穴内部保留1.2m可探索净长，上方有岩体覆盖；背部封口不是用一道独立薄墙遮住。
ST015：骸骨集中在凹穴北侧深处，靠近收束处，禁止留在入口/通道。保存骸骨中心布局以校验真实几何，不改骨色与扫描来源。
ST015补充：骸骨深处与原碎石簇及地面矿物发生重叠，碎石移至岩体外侧，对骸骨所在区域留白；增加实际射线可见性检查，防止只满足位置却被装饰埋住。检查镜头在凹穴内，不代表入口所有角度均无遮挡。

ST016（最新左岩壁验收）：取消岩体下缘的大面积拱形悬空，岩脚在前/中/后连续落地，南端侧边凹穴入口仍保留，不能从岩体正下方开通道。岩冠由南侧约2.2m逐渐升至北侧4m接顶。前断面增加实际层理起伏与细节纹理，不能保留平滑封边。左岩体旁贯穿石柱改为短石笋，保持右侧已设矿物及滴水。此条替代旧ST013下缘大拱口及ST004左侧贯穿柱要求。
左岩壁独立评分：整体轮廓/前后关系30、落地和凹穴25、正面层理25、短石笋及接触10、材质衔接10。80分为内部审阅门槛，必须记录实际截图看到的不足，不等于用户认可。

ST017：后续主要建模对象执行 ../../lethal-dungeon/docs/06-房间逐物体验收流程.md。先拆分清单，单物体实际对照迭代达到80分，再进入下一个对象；用户已认可0.6/R13左岩壁达到80分，其余对象不自动认可。

ST018：左凹穴内的西墙扫描面和底层西墙都要闭合至X=-4背面，保留朝内表面，不用双面渲染冒充厚度；主岩体几何保持R13。优先复用已有材质。
ST019：左岩体下方只保留少量前方外侧短石笋（本版3根），移除内侧成簇地面石笋；右侧与天花板滴水不变。
ST020：左岩脚崩落碎石改为细分的破裂岩体，保留不规则断面、磨损棱边、多尺度表面细节与PBR，不沿用几面体。主要对象按ST018→019→020依次实际审阅到80分才继续，记录在专项审阅文件。

ST021：替代旧近等厚ST012：主岩体前缘较薄、中腰厚、后部向母岩收束，厚度随纵深和高度共同变化（约0.34–1.1m），多截面实际厚度差至少0.35m。保留落地、前低后高、后端封闭、骨堆与通路。前侧过渡使用连续扫描UV及跨UV缝平滑法线，不用异色封边带；保留层理而非磨成平板。

ST022（最新布局纠正，替代ST010/012/021的固定长度及厚度范围）：岩壁南端对齐右侧主潭北端附近（Z约-1.68m，容差0.3m），后端仍接母岩。不能为了旧5–6m指标向入口过度延长。主要可见截面厚度与内侧净空宽度应同量级（约0.8–1.4倍），保留中腰鼓出与前后变化；不能靠缩窄凹穴达标。入口左半侧玩家眼高1.6m应能发现深处骸骨，不再用凹穴内部镜头冒充入场可见。短石笋随前缘重新定位。

结构评分新标准：比例/厚度与负空间25，纵深起止及相邻物体对齐20，玩家入场视线20，曲率/前侧转角15，落地接顶封口20；逐项对照参考与实际渲染。前三项任一明显错误时结构分最高59/100，单体不能判80。射线仅验证视线，不能替代截图中是否可辨认。此前R15结构自评缺少厚度/净空比及入场检查，撤回达标结论。

ST022补充替代ST015旧绝对骨堆坐标：骨堆随缩短布局移到凹穴口内侧、仍靠西墙和岩体内面，不再要求Z>0的旧最深处位置。岩壁本身后端封闭与可探索净空保留。实际入场能辨认骨形才算通过视线项。

ST023：已知明显纹理拉伸、穿模属于阻止交付的问题，不得仅列扣分后交付。封边UV不得以sin往返复制扫描边缘导致折返/塌缩；前断面使用按真实米制展开的岩石纹理，颜色/法线/粗糙度共用UV。检查正面和转角，不以增加纹理噪声隐藏问题。
ST024：石笋定位检查完整半径、高度和倾斜包络，不只检查中心点。3根短石笋置于岩体前外侧，彼此留出距离；从地面以上多个高度检查朝向岩体的净距，根部可接泥土，主体不得埋入岩体。原ST019单点射线不足，替换为全高度检查。

ST025：主岩体正侧面及西墙采用同一世界空间岩石投影，烘焙进GLB，不允许继续用异色封边材质形成补丁；光照无关的颜色连续性必须跨原封边成立。保留真实扫描几何起伏，圆顺前缘连接，底部埋入地面而不沿整条岩脚露黑缝。西墙扫描层边缘收回母岩，不露薄片。
ST026：岩脚三根石笋呈非共线疏落分布，配局部低矮沉积根部；碎石以片状断裂为主，不保留三个圆石抱团的摆件感。保留通路、凹穴、入口骸骨可见及滴水落点。
ST025烘焙：bake-rock.mjs 把三向世界空间PBR投影烘焙为自包含GLB纹理，正侧面与西墙使用同一材质投影。当前审阅烘焙8192图集、共13张嵌入图片；手机资产需另做图集压缩/LOD，此为审阅产物。为避三角小图块的mipmap串色，烘焙图集使用线性过滤；不能将高分辨率烘焙宣称为手机优化。

烘焙缓存：public/textures/unified-rock-cache.json 仅作生成加速；签名包括投影源代码、三张源贴图、目标几何及法线，变化自动重烘焙。清除此文件可强制重烘焙。图集、UV与法线方向必须一起校验，不能只替换图片。审阅AO半径0.16m、最大距离0.10m；实体岩脚下沉并与地形沉积连接后才调整接触阴影。

ST027（用户新增造型思路）：主岩体按外面→正外过渡→正面→正内过渡→内面五个视觉区域组织，保持单一连续材质，不能变成五块拼接平板。两段过渡使用近相切圆弧，正面略向南鼓出，保留体积、凹穴与水潭相对位置。此轮不重做墙面风格。
ST028（用户新增氛围思路）：骸骨稍向北移，入口仅能发现小部分，不要求完整显露。入口取样可见比例控制约10%–35%，仅作回归约束，最终以实景里“露出一小半”的感觉判断；洞内靠近后仍能看清。此前较完整显露符合当时要求，不记为历史失误。

ST029：R19仅圆边仍未读出正外面，撤回“五面已完成”结论。两段斜面需要约0.35–0.5m的实际可见宽度，并沿纵深接回内外面；先收回肩部接点，再形成较宽的斜向曲面与略鼓正面，不只在原窄边上加法线。沿中段高度分别检查正内/正外斜面面积和用户侧视角中的宽度，最后保持统一PBR。

ST030：用户对R20/0.13左岩壁给85分，保护该版几何。仅将主岩体材质略压暗，线性RGB乘色[0.78,0.80,0.83]，在烘焙后应用并嵌入GLB，不能用全局曝光代替。骸骨北侧补独立种子的精细断裂碎石堆，尺寸/姿态不同、贴地堆叠；完整包围盒不得覆盖骸骨，保留入口半遮掩与洞内视线。骨色和位置不改。

ST031：用户指出室内洞顶两侧条板状接缝。删除旧叠层顶唇的独立上下板/竖边，洞顶与侧部过渡共用连续起伏高度场、米制UV和法线；靠墙逐渐下弯，不能由一圈直立侧面形成台阶。剖顶预览可分开显隐，但连接处必须同高同法线。小钟乳石根部按局部洞顶埋入，保留原尖端、滴水落点和已认可主岩体/骸骨/碎石。

ST032：增加仅用于检查原门位墙面的封墙审阅导出。buildRoom({closedWalls:true})生成完整南北岩壁，沿整面延续起伏及UV，不用平板填洞；默认buildRoom()仍保留配置示例门及通路。封墙GLB单独保存为straight-wet-karst-closed-walls.glb，标记previewWallMode=closed，不作为随机门位模块已完成的证明。
ST032导出补充：封墙审阅副本三张统一岩石图集按4K嵌入，避免本次浏览器8K加载失败；源8K图集及默认开门模型不变。UI当前默认完整洞顶室内视角，下载指向封墙副本。

ST033：蜘蛛网不能用不透明规则金属线表现。改为灰白半透明细丝，关闭透明丝的深度写入；支撑丝与捕获丝粗细不同，网眼疏密、松弛和断丝使用独立种子。保留原所在区域，实际室内及近景检查，不用发光材质。GLB保留BLEND材质。

R23/0.16：蛛网换为灰白半透明丝质（opacity 0.48，roughness 0.78，非金属，不写深度），支撑丝和捕获丝粗细分开，网眼间距与破损独立随机，局部松弛下垂。网上下载的两份素材风格不合适，未采用，筛选记录见evidence/rejected-assets/README.md。封墙审阅图集4K、其他贴图限制2K以降低内存；原始素材和默认导出仍保留原分辨率。GLB导入网页需恢复透明材质depthWrite=false（glTF不表达该字段）。
ST034：右侧网身向洞内退离原位置0.38m，避免被实际凸出岩壁吞没；仅三处连接丝射线接回真实岩面。内存按网格属性和索引数组byteLength报告，不把它当整页或GPU进程实测。

ST035（替代ST034布局）：撤销墙面中央扇形网以及平移38cm的修补方案。蜘蛛网改为东北上方角落的小片积网，锚点射线定位在东/北两个真实岩面，网身跨角落悬垂；不再出现单个中心的放射扇面。几何全体限制于角落，不占墙面中部和通路。先验证角落位置/跨面锚点，再检查实际室内及斜侧近景。

ST036：用户认可R24位置，但要求把渔网状积网替换为平面圆网。保留东北角跨面锚点，网身为近圆轮廓、放射支撑丝及连续螺旋捕获丝，轻微不对称；不得沿用三角网格。网身共面，只有边缘牵引丝离开网平面接回岩面。此前找到的下载文件不是可直接复用的写实圆网3D模型，不虚称使用了该模型。

ST037：至少6根牵引丝必须沿已存在的放射丝共线延伸，不独立计算折向锚点。由对应网缘沿中心→网缘方向射线求真实岩面首个交点；保存放射丝编号、网缘、落点，验证共线、唯一编号、真实接触及角落范围。圆网主体和已认可位置保持。

ST038：牵引丝须覆盖圆网局部平面的左上、左下、右上、右下四象限，各至少1根，优选各2根。旧锚点Y>2.12限制误删下方支撑，改为约束圆网主体仍处上方角落，牵引丝可向下连接岩面。圆网外侧增加两道疏密不同的横向加固丝，端点接在相邻牵引丝上；保持原放射共线。

2026-09-09 用户验收：R27/0.20 蜘蛛网单体获95分，已认可。后续复用基准：角落悬挂的平面圆网；放射丝与螺旋捕获丝；左上/左下/右上/右下各2根共线外延支撑丝，实际岩面落点；网外两道横向加固丝；半透明丝质。保护此结构，不能退回墙中央扇网或三角渔网。评分仅限蛛网，不代表整房95分。
