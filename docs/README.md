## 当前已确认

- 团结引擎方向，面向微信及国内小游戏。
- 城镇准备→马车出发期间生成地图→1–4人地下城搜集搬运→午夜前撤离→回城。
- 支持1–4人出发，单人可走完整测试流程；不自动改变必须队友救援的怪物机制。
- 活人在马车处发令即可撤离，车外队员被遗弃；午夜未撤离失败。
- 到达06:00，现实1秒＝游戏1分钟；统一服务端时钟，加载不计时，到达后无安全期。12分钟抵达18:00建议撤离时段，18分钟抵达午夜硬截止；“12分钟节奏目标”的解释待确认。
- 服务器生成多高度预制模块布局，客户端搭建；地下城永久不可破坏。
- 每人默认10格财宝，空包移动1.2，满包0.9；已确认线性公式：倍率＝1.2−0.03×已占格数，5格为1.05。
- 死亡或失败损失随身装备和未运回财宝，城镇仓库与金币保留。
- 两项战斗属性：血量与攻击；初始系数0.5、顶装0.9；同系数三击击杀。
- 仅上身、下身、武器三个装备位，战斗数值对玩家尽量隐藏。
- 11种怪物按用户最新描述保留，重复编号已整理，无新增原作机制作为既定规则。

## 已确认的研发要求

- 模块规范先行，先在每个模块的`README.md`披露职责、契约、约束、禁止事项和测试说明。
- 测试驱动开发（用户所称TTD按TDD理解）：先写充足用例并验证合理失败，再实现，再重构与回归。
- 遵循项目AI Harness约束：依据仓库规范、明确修改边界、规则映射测试、真实记录验证结果。
- README、测试与实现共同交付；未运行的测试不记为通过。首批纯C#测试工程已建立，远程CI已建立，但作业因GitHub账号账单锁未能启动。

## 下一轮优先评审

1. **数值含义：**是否采用 H=30s、A=10s；接受巨人、冤魂、幽影、树人一击杀顶装玩家吗？
2. **史莱姆：**分裂是否分配受击后剩余血量，而非每个子体满血？
3. **回城与损失：**已装车但撤离失败的财宝是否也损失；成功货物如何分配？
4. **机制计时：**1分钟、5秒、3秒是否均为现实时间；宝箱吞食多久致死，寄生僵尸的血攻和移动如何设定？
5. **视角与沟通：**是否采用第一人称；实时近距语音是否为首版必需？
